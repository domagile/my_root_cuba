# Производительность поиска и массовой синхронизации

Ветка `perf/bulk-sync-and-search` основана на `fix/restore-family-memberships` (`1b3f856`). Замер выполнен локально 25 ноября 2026: Node 24.15.0, darwin x64, одинаковая машина и синтетические данные. Данные пользователей и платные API не использовались.

В массовой синхронизации повторные Array.find/Array.some по всему списку заменены одним индексом. Для единичных правок индекс не создаётся. Проверка результатов изменения отметок удаления использует Set. Сохраняются выбор первой записи для старых дублирующихся ID, обработка частичных ошибок, порядок удаления/записи и защита новых локальных действий.

Поиск переиспользует результаты одинаковых сравнений текста и пар слов внутри одного запроса. Алгоритм сопоставления, языковые правила, оценки, категории и порядок результатов не менялись. Временные таблицы ограничены: до 10 000 текстов и до 20 000 пар в каждой таблице. Достижение предела отключает добавление новых элементов кэша и не исключает кандидатов. Между разными запросами эти таблицы не сохраняются.

Замер синхронизации включает работу контроллера с немедленно отвечающими заглушками облачных записей. Создание фикстур, заполнение dirty tracker, запись IndexedDB, сеть, Firebase и действия пользователя в UI в интервал не входят. Синтетические данные содержат повторяющиеся имена и заметки; выигрыш на других данных может отличаться. Поиск проверяет наличие ожидаемого результата, отправка — число записей и успешное завершение.

Раскладка измерялась на синтетическом дереве, с глубиной 4 и отключёнными мостиками линий. Её алгоритм в этой ветке не менялся; небольшие различия времени не объявляются ускорением. DOM/SVG, FPS, GPU и время от нажатия до перерисовки не измерялись. Первый поиск на 10 000 персон всё ещё занимает примерно 1,5 секунды на этой выборке.

## Potential defects & technical risks

- Показатели не доказывают ускорение реального Firebase или браузерного рендера. Проверка стенда: большой тестовый родословный набор, первый и повторный поиск, переключение выбранной персоны и массовая отправка с записью CPU-профиля и времени интерфейса.
- На данных с уникальным длинным текстом повторов меньше и эффект memo-таблиц может быть ниже. Ограничение памяти не должно менять результаты; при его достижении используется исходный расчёт.
- Поиск в текущем UI остаётся синхронным. На очень больших наборах даже уменьшенная задержка может потребовать Worker или отдельного поискового индекса. Эти изменения в этой ветке не выполнялись.
- Это не проверка всех правил поиска и всех возможных ошибок данных. Сохранение очереди при сбоях, старых ответах и квоте дополнительно проверяется существующими наборами синхронизации и корзины.
