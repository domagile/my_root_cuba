# Камера и клавиатурное управление деревом

Локальный этап от 26.11.2026, продолжение `tree-viewport-interactions.md`. Основание — согласованная задача восстанавливать положение/масштаб и управлять меню с клавиатуры. Jira не используется; критерии ниже являются техническими ожиданиями задачи.

## Изменения

- При открытии дерева восстанавливается корректная сохранённая камера выбранной персоны. Первичное центрирование больше не заменяет её масштабом 95%. Если камера повреждена, относится к другой персоне или оставляет экран полностью пустым, дерево центрируется на текущей персоне. Явная смена корня сохраняет прежнее центрирование нового корня.
- Версия `viewport.version=1` связывает камеру с ID персоны независимо от отдельных записей выбранной персоны. Новый формат допускает настоящие координаты 0/0 и 80/80; старый формат читается с прежним исключением этих служебных значений.
- Настройки читаются через существующий синхронный буфер локального хранилища: последующее сохранение не теряет ещё не завершённую запись. Фильтрация старого формата не изменяет объект в буфере.
- При закрытии раздела сохраняется последний завершённый React commit, даже если задержка автосохранения ещё не истекла. При скрытии/закрытии страницы используется существующий аварийный сброс локальных записей. Незавершённая ошибка IndexedDB остаётся в общей очереди.
- Меню родителей и братьев/сестёр имеют доступные обозначения раскрытия и связи с диалогом. Enter/Space открывают меню и переводят фокус внутрь; Escape и подписанная кнопка закрытия возвращают фокус на кнопку открытия. Tab и внешний клик закрывают меню, сохраняя естественный переход фокуса.

## Выполненные проверки

204 локальных теста: основной регрессионный прогон, отдельно trash 37 и production server 3; после изменения очистки настроек повторно прошёл весь набор дерева — 54 (24 раскладки, 14 сравнения карточек, 5 границ, 11 настроек). В дерево добавлены 11 проверок форматов камеры, привязки к персоне, видимости, ожидающих записей, разделения пользователей, повреждённых настроек и очистки перед завершением предыдущего сохранения. Повторы не включены в число 204. TypeScript и production build прошли.

31 браузерный сценарий: 24 настоящего TreeView и 7 прежних проверок карточек. Новые сценарии покрывают оба меню через Enter/Space/Escape и кнопку закрытия, Tab/внешний клик, старую камеру, версионированный ноль координат, быстрый unmount/remount в StrictMode, настоящую перезагрузку страницы до автосохранения, смену корня, пустую/чужую камеру и другого пользователя. Ошибок страницы и внешних запросов нет.

Проверки выполнены в Chromium 153.0.8010.12, Playwright 1.63.0 на синтетических данных. Авторизация и облачный API заглушены; локальные IndexedDB и localStorage настоящие. Рабочие записи не менялись. Запуск: `npm run test:tree`, `npm run test:tree-view-browser`, `npm run test:tree-browser`; для браузера нужен установленный Playwright/Chromium, путь модуля может задаваться `PLAYWRIGHT_MODULE`.

## Potential defects & technical risks

В выполненных сценариях подтверждённых незакрытых дефектов нет. Ограничения: сохранение относится к пользовательскому профилю и персоне, без нового разделения по проектам; отдельные свёрнутые ветки не сохраняются этим этапом. Вход в другой профиль без повторного открытия дерева не запускает восстановление его старой камеры. Рабочий Firebase, реальная оболочка приложения и физические мобильные устройства не проверялись. Для приёмки следует повторить переключение разделов и профилей в приложении на пользовательском дереве. Этап сохраняется локально, без GitHub/деплоя.
