# Проверка загрузки изменений в Firestore

Пользовательское требование: нельзя показывать synced и очищать очередь,
не проверив результаты операций загрузки.

Исправлены автоматическая загрузка из GenealogyContext, ручная обычная/полная
загрузка и быстрая отправка изменений персон. Их обработка очереди выполняется
последовательно. Данные и номер ревизии берутся при начале обработки задания.

Правила подтверждения:

- Успешной считается только операция, вернувшая true. false, исключение и
  отсутствие локальной записи для ожидающей операции считаются неуспехом.
- При частичном успехе весь пакет остаётся в очереди для повторной отправки.
  Повторные merge/delete идемпотентны. Это консервативное решение: уже успешно
  отправленные операции пакета тоже могут быть повторены.
- Отдельный сохраняемый признак незавершённого пакета не позволяет быстрой
  записи персоны скрыть ошибку общей загрузки или её метаданных. Неудачная
  полная загрузка сохраняет необходимость повторить именно полный снимок.
- Очередь очищается после успеха всех операций, если ревизия локальных правок
  не изменилась. Повторное редактирование той же записи тоже меняет ревизию.
- Быстрая отправка персоны включает всю накопленную дельту. Она не подтверждает
  более новую дельту и не заменяет требуемую запись полной персоны.
- Квота Firestore возвращает неуспех/состояние offline. Очередь остаётся;
  локальная резервная копия не является подтверждением загрузки в облако.
- Последняя успешная операция из параллельных атомарных записей не маскирует
  предыдущую ошибку. Время последней подтверждённой синхронизации при ошибке
  сохраняется.
- Неподтверждённые изменения отображаются как pending в Header и Settings.
  Снятие флага квоты и чтение обновлений из облака не обходят проверку очереди.
- Частичная загрузка передаёт общие счётчики коллекций отдельно от изменённой
  выборки, чтобы не записывать размер дельты как размер всей коллекции.

Автоматическая отправка повторяется после новых правок или события online.
В ручном режиме повтор выполняется кнопкой загрузки. Если во время отправки
появились новые изменения, результат не разрешает продолжить цепочку Full Sync
автоматическим скачиванием старой облачной версии.

## Локальные автоматические проверки

```sh
npm run test:sync
npm run lint
npm run build
```

Тесты используют управляемые ответы API и MemoryStorage, без Firebase app,
проектной конфигурации, подключения к рабочей базе и реальных записей.

| Группа | Проверяемое требование / риск | Число тестов |
| --- | --- | ---: |
| Атомарные результаты | false, исключение, ошибка перед последним успешным ответом | 3 |
| Авто и ручная загрузка | Отказы записи персоны, исключение, удаления, загрузки остальных данных; успешный повтор | 8 |
| Полнота пакета | Отсутствующая локальная запись, исследовательские коллекции, удаления при полной загрузке | 3 |
| Квота | До отправки, во время отправки, снятие флага при незавершённой записи | 3 |
| Новые правки и координация | Изменение той же персоны, правки во время бекапа, массовые изменения, порядок заданий, быстрый ответ после ошибки пакета | 5 |
| Быстрая отправка | Накопленные поля, новая дельта во время записи, обязательная полная запись | 3 |
| Статусы и метаданные | Защита статуса, восстановление очереди заданий после исключения, общие счётчики | 3 |
| Итого | | 28 |

Это проверки обработчика очереди и состояния. Работа через браузер на
развёрнутом стенде в этом изменении не проверялась. Регистрация операций,
которые сейчас обходят dirtyTracker, и отказ локального хранилища требуют
отдельной проверки; этот набор не означает полное покрытие приложения.
