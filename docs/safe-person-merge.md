# Безопасное объединение особ — 26.11.2026

Изменения подготовлены по запросу пользователя: улучшить объединение дубликатов и затем отправить готовый код в отдельную ветку GitHub. Jira для этой задачи не использовалась. Ниже приведены технические критерии выбранного решения, а не вымышленные требования Jira.

Перед объединением сохраняется подтверждённая контрольная точка в IndexedDB. Если её транзакция не завершилась, записи не меняются. Особы, семьи, корзина, журнал удалений, соответствие «дубликат → основная особа» и указатель на контрольную точку сохраняются общей локальной транзакцией. При ошибке этой записи интерфейс сообщает о неподтверждённом сохранении, очередь остаётся доступна для повтора, отправка в облако ждёт успешного локального сохранения.

Кнопка «Скасувати останнє злиття» находится в верхней панели у пользователей с доступом к редактированию. Отмена восстанавливает записи и семейные связи, снимает служебные отметки удаления/слияния и ставит восстановление в очередь синхронизации. После содержательных изменений особ, семей или корзины автоматическая отмена отказывается перезаписывать данные. Только серверный updatedAt и эквивалентные пустые значения null/undefined не считаются содержательной правкой. Последовательные слияния можно отменять в обратном порядке, пока сохранены контрольные точки и нет других изменений.

Объединение больше не вызывает «Не дублікат». Это отдельное пользовательское решение. Ошибка слияния не скрывает пару, а пропущенные пересекающиеся пары пакетной операции не получают отметок об обработке. Устаревшее сравнение и повторное нажатие отклоняются. В диалогах ошибки показываются пользователю, успешное закрытие происходит после завершения операции. Выбор основного ID во вложенном мастере теперь определяет и выбранную особу после слияния.

## Potential defects & technical risks

- Автоматическая отмена консервативна: изменение любой особы, семьи или корзины блокирует её, даже если правка не относится к объединённой паре. Это защита от потери последующих изменений. Проверка: объединить пару, изменить другую запись, нажать отмену; новая правка должна остаться, контрольная точка — сохраниться. Проверено автоматически и в браузере для правки записи.
- Контрольные точки принадлежат текущему браузеру; действует существующий лимит 20 снимков. Удалённая/вытесненная точка недоступна для отмены. Перенос этих точек вместе с экспортом проекта не добавлялся. Отказ при отсутствующей точке проверен; поведение очистки браузера требует пользовательского резервного копирования.
- Firestore сохраняет разные коллекции несколькими операциями. Очередь поддерживает повтор при частичной ошибке, но это не общая атомарная транзакция всей удалённой базы. Эмулятор проверяет отдельные транзакции служебных настроек, а не работу на производственных данных.
- Две вкладки с разными версиями приложения и старые клиенты, перезаписывающие карту слияний целиком без обновления revision, отдельно не проверены. После публикации новой версии следует обновить открытые вкладки. Для проверки нужен отдельный сценарий с двумя клиентами, включая старую сборку.
- Production-данные не изменялись. Передача кода в GitHub не означает развёртывание приложения и не включает слияние этой ветки в main.
