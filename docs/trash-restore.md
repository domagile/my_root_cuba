# Восстановление персон из корзины

Дата проверки: 25 ноября 2026. Ветка: `fix/trash-restore-tombstones`, база: `3a0e6b7`.

Одиночное и массовое восстановление используют один путь: выбранные записи возвращаются в активный список, удаляются из корзины и сразу перестают считаться удалёнными. Повторяющиеся ID не создают дополнительные записи; уже активная запись сохраняется. Неизвестный ID ничего не изменяет.

Журнал локальных намерений удалить/восстановить хранится в IndexedDB вместе с данными. При повторном запуске он снова ставит синхронизацию в очередь. Подтверждение снимает только ту версию операции, которая действительно отправлялась. Сначала подтверждается запись персоны, затем транзакция изменяет её отметку удаления. Ошибка, исчерпание квоты или неподтверждённый результат оставляют операцию для повторной попытки.

Серверная транзакция изменяет отметки по ID и сохраняет независимые удаления других клиентов. Локальная обработка подтверждений также сохраняет независимые отметки, полученные подпиской во время запроса. Подписка принимает только подтверждённые сервером снимки, включая переход из кэша к серверному подтверждению. Фоновая загрузка и подписки начинаются после чтения локальных данных.

## Potential defects & technical risks

Ниже — ограничения и потенциальные риски по исходному коду; браузерные сценарии не выполнялись. Они не объявляются подтверждёнными дефектами стенда.

1. **Семейные связи и отмена объединения.** R1 относится к записи персоны. Полное восстановление связей отдельно не задано. `deletePerson` в `src/stores/useGenealogyStore.ts` удаляет ссылки из семей, а `restorePersons` не содержит их исторической копии. Дополнительно `GenealogyProvider` исключает ID из `genealogy_merged_person_ids`. Сценарий для стенда: создать супругов и ребёнка, удалить и восстановить персону; отдельно попытаться восстановить объединённый дубль. Нужно согласовать, должно ли восстановление отменять эти изменения. Текущая правка не обещает восстановления утраченных связей или отмены merge.

2. **Корзина другого устройства.** R5 покрывает независимые облачные отметки, но не полную согласованность всех локальных корзин. `GenealogyProvider` в `src/context/GenealogyContext.tsx` дополнительно фильтрует облачных персон по локальному `trashPersons`. Сценарий: удалить на A, восстановить и отправить на B, обновить A. До отдельного согласования корзин A может продолжить скрывать запись. Если нужна автоматическая синхронизация корзин, следует определить правила конфликтов и проверить оба клиента.

3. **Записи из пути чтения.** Полностью безопасная загрузка — отдельная работа, не R1–R7. В `GenealogyProvider` остался вызов `deletePersonDoc` при исключении облачной записи по локальным фильтрам. Сценарий: у A устаревшая корзина, B восстановил персону, A получает обновление. Проверить, не удаляет ли A восстановленный документ. Ожидаемое поведение нужно определить для согласованной политики конфликтов; этот путь здесь не переработан.

4. **Одновременные противоположные действия над одним ID.** R5 подтверждён для независимых ID; политика разрешения конфликтов одного ID не задана. Сохранение персоны и отметок — отдельные операции, транзакция охватывает список отметок. Сценарий: A восстанавливает P, B одновременно удаляет P, ответы приходят в разном порядке. Проверить согласованность документа, отметки и обеих корзин. Для гарантии на нескольких устройствах потребуются версии операций и согласованное правило конфликтов.

5. **Браузерная проверка перед выпуском.** R7 проверен чтением кода, не UI-тестом. На тестовом профиле с резервной копией: удалить A/B/C, быстро восстановить A и B по очереди, перезагрузить страницу; повторить массовым восстановлением; отключить сеть перед отправкой и повторить отправку после восстановления сети. Проверить активный список, корзину и отметки, затем повторить в режимах manual/auto. Реальный браузер и производственный Firebase этим отчётом не покрыты.

Исправление изолировано в отдельной ветке. Откат кода выполняется возвратом этой ветки или отменой её коммита; уже синхронизированные пользовательские действия требуют отдельного решения и не отменяются откатом исходного кода.
