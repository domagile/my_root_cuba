# Кеш дерева: исправление и оптимизация

База сравнения: 3a0e6b70f20f096f88ef2daedcd1ad1f576384da, 25.11.2026.
Работа ведётся отдельно от правки меню. Jira issue для неё не задан;
критерии ниже — инженерные условия прозрачности кеша по запросу об оптимизации.

Ранее ключ включал количество людей/семей и lastModified. В RodovidView
lastModified имеет фиксированное значение. При прежнем количестве записей
редактирование человека или смена семьи могло получить старый результат,
а разные базы с одинаковыми ID — использовать общий результат.
На синтетическом примере изменение Before → After возвращало Before до очистки кеша.

Исправление использует идентичность снимков persons/families и сигналы ревизии,
не перебирая все записи при попадании в кеш. Реестр идентичности использует WeakMap;
каждый кеш схем ограничен 40 результатами. Чтение продлевает срок жизни результата
по LRU. Индекс родства проверяет ту же ревизию и сбрасывается общей очисткой.
Параметры круговой схемы нормализуются до выбора кеша, включая потомков,
переопределение цвета и явно заданные нулевые размеры.

## Узкий замер производительности

Команда: bun run bench:tree. Node.js 24.15.0, синтетические 10 000 людей,
1000 повторных попаданий в кеш вертикального дерева, пять серий после прогрева.
Скрипт одинаков для исходной и изменённой реализации. Зависимости закреплены тем же bun.lock.

| Реализация | Медиана времени 1000 обращений |
| --- | ---: |
| Исходная | 1500,33 мс |
| Исправленная | 1,66 мс |

Ускорение объясняется устранением полного Object.keys для обеих коллекций
на каждом попадании в кеш. Это информационный замер одной операции;
он не измеряет время рисования дерева, холодный расчёт или отзывчивость приложения
в браузере. Абсолютные времена зависят от машины и нагрузки, порог в CI не задан.

## Potential defects & technical risks

- **Изменение на месте.** Код приложения должен заменять persons/families при
  редактировании либо менять version/lastModified или явно очищать кеш после
  изменений внутри прежних объектов. Определение произвольной глубокой мутации
  без такого сигнала потребовало бы сканирования данных и не входит в исправление.
  Стендовый сценарий: отредактировать имя и родителя обычными формами, затем открыть
  вертикальное, горизонтальное дерево и круговую схему; проверить актуальные карточки
  и связи без перезагрузки. Полный сценарий в браузере не исполнялся.
- **Скорость холодного расчёта.** Основные алгоритмы построения геометрии и поиска
  родства не переписаны. Для больших связанных деревьев нужны измерения отдельно
  от кеша: раскрытие ветвей, масштабирование, наведение и переключение корня.
- **Широкие подписки состояния.** GenealogyContext передаёт общий объект 25
  потребителям; это кандидат на отдельную оптимизацию через точечные Zustand
  selectors. Снижение количества перерисовок пока не измерено и не заявляется.
