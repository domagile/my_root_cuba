# Сохранение выбора «Не дублікат»

Локальное исправление от 26.11.2026. Требование пользователя: после выбора «не дубликат» та же пара не должна снова предлагаться без явной обратной команды. Jira в этой задаче не используется. Рабочая база не изменялась.

## Причины в прежнем коде

- `GenealogyContext.triggerDownloadFromCloud` заменял локальные исключения полным облачным массивом, включая старый или пустой список.
- `saveIgnoredDuplicatePairsToCloud` возвращал `false` в ручном режиме. Вызывающий код учитывал только исключение Promise и не сохранял очередь для следующего явного выведения в облако.
- При автоматической записи отправлялся полный массив ключей. Поздний ответ или независимый выбор другого клиента могли заменить весь список.
- Worker получал снимок исключений при запуске и мог завершиться после нового выбора пользователя. Карта дублей дерева также обновлялась только после отложенного повторного сканирования.

Это выявленные пути потери выбора, а не утверждение о том, какой именно путь сработал в пользовательском браузере. В локальных сценариях старый/пустой облачный список подаётся явно.

## Исправление

- Каждое добавление/удаление исключения сохраняется в локальном журнале с токеном операции. Ожидающие решения накладываются на облачный список и не исчезают при скачивании. Ошибка локального/облачного сохранения не подтверждает операцию.
- Выбор включён в общую очередь синхронизации: в ручном режиме остаётся локально до явной отправки; в автоматическом уходит обычным процессом синхронизации. Устаревший вызов полной перезаписи удалён.
- Облако изменяется транзакцией только для указанных ключей. Монотонная ревизия позволяет отклонять более старые снимки после подтверждения. Чужие независимые решения сохраняются.
- Подтверждение удаляет только совпадающие токены. Новое противоположное решение, сделанное во время отправки, остаётся ожидающим. Явная команда вернуть пару в проверку продолжает работать.
- Исторические форматы ключей и обратный порядок ID поддерживаются. Старые локальные исключения сохраняются до подтверждённого переноса; непрозрачные старые ключи не разбираются предположительно и не теряются.
- Гидратация читает журнал IndexedDB; более новая аварийная копия после закрытия страницы защищена локальной ревизией от старой завершённой транзакции.
- Карта дублей дерева фильтрует текущий выбор сразу. Результат Worker с включённым фильтром повторно проверяется по актуальным исключениям перед возвратом. Необязательный родительский callback диалога больше не вызывает повторную запись того же выбора; обработчик также идемпотентен.

## Potential defects & technical risks

В выполненных сценариях незакрытых подтверждённых дефектов нет. Полная рабочая оболочка с реальным Firebase не запускалась; для приёмки следует отвергнуть пару, повторить поиск, скачать настройки, перезагрузить и явно отправить изменения в текущем режиме синхронизации. Старые вкладки/клиенты после публикации должны обновиться: старый код полной перезаписи не соблюдает новую ревизию. Одновременные записи общего локального журнала из двух вкладок одного браузера отдельно не проверены; два независимых облачных клиента проверены в Emulator.

Исключения относятся к ID двух персон: создание новой пары с новыми ID при импорте требует нового решения. Ранее уже стёртые записи выбора не восстанавливаются из отсутствующих данных. При первом переносе старого формата приоритет отдан сохранению существующих локальных исключений, поскольку история их прежних облачных подтверждений отсутствует. JSON-экспорт журнала не добавлялся. Миграция выполняется локально; публикации в GitHub и деплоя на этом этапе нет.
