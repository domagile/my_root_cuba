## Potential defects & technical risks

1. **Авторизация и расход AI API.** В createApiApp маршруты распознавания пока
   не проверяют Firebase ID token и серверную роль. При публичном размещении
   посторонний может обращаться к платному API. Основание: технический риск,
   бизнес-политика допуска к распознаванию не предоставлена. Стендовый сценарий:
   запрос без входа с валидным сканом; затем viewer/editor, параллельные запросы
   и лимиты. До публичного размещения требуется согласовать доступ и ограничение
   расходов. В этих тестах Gemini подменён; проверки атаками рабочей системы не было.
2. **Границы резервной копии.** createProjectArchive не сохраняет отдельные заметки,
   корзину, маркеры удаления/слияния, интеграционные настройки и двоичные вложения.
   Ожидаемое поведение полного аварийного восстановления надо согласовать отдельно.
   Стендовый сценарий: экспортировать дерево с этими объектами и восстановить в
   чистом профиле; отдельно проверить ранее удалённого или объединённого человека.
   Этот пакет не заявляет успешное полное восстановление таких случаев.
3. **Аварийное закрытие браузера.** Очередь с ошибкой остаётся в памяти;
   beforeunload является best effort, браузер может не показать предупреждение.
   Стендовый сценарий: запретить IndexedDB/заполнить квоту, изменить большое дерево,
   проверить предупреждение и повтор. Принудительный kill до commit может потерять
   неподтверждённые изменения; это ограничение явно отражено в UI/README.
4. **Интеграционная проверка.** Изменения экранов распознавания (реальный выбранный
   скан, отдельные ID загрузок, устаревший ответ после смены скана) требуют smoke
   в браузере. Стендовый сценарий: сканы A/B, медленный ответ A, переключение на B,
   затем добавление кандидата и повторное открытие. Автотесты покрывают API и
   преобразование кандидата, но не этот полный UI-сценарий.
5. **Рабочие правила и whitelist.** Наличие защищённых правил в GitHub не доказывает
   их публикацию. Перед деплоем нужны проверка доверенности текущего whitelist,
   вход владельца через Google и гостевая проверка публичной ссылки по
   docs/firestore-security.md. Рабочая база в ходе задачи не менялась.

Доставка кода не выполняет deploy Firebase. GitHub Actions запускает только проверки.
