# Родовід / My Root Cuba

Генеалогическое приложение: React, Zustand, IndexedDB, Firestore и Express.

## Локальный запуск

Проверенная среда: Node.js 24, Bun 1.4.5. Для тестов правил Firestore нужен Java 17
и локальный эмулятор; версия Firebase CLI закреплена в bun.lock.

```sh
bun install --frozen-lockfile
cp .env.example .env
bun run dev
```

Ключ GEMINI_API_KEY задаётся только в серверном .env или в секретах хостинга.
Без ключа дерево работает, а распознавание возвращает явную ошибку 503.
Демонстрационные сведения не подставляются вместо результата анализа.
GEMINI_MODEL можно изменить на доступную в вашем аккаунте модель;
значение по умолчанию — gemini-3.8-flash ([документация модели](https://aistudio.google.com/docs/models/gemini-3.8-flash)).
Запрос к модели ограничен 45 секундами, клиентское ожидание — 60 секундами.

## Проверки перед доставкой

```sh
bun run lint
bun run test:sync
bun run test:storage
bun run test:api
bun run test:firestore
bun run build
bun run test:server
```

Тесты распознавания используют подменённый провайдер и не расходуют квоту Gemini.
Тесты Firestore обращаются только к локальному emulator проекта demo-my-root-cuba.
Тест запуска сервера проверяет готовую сборку, поэтому выполняется после build.
Те же команды включены в GitHub Actions; развёртывание workflow не выполняет.

## Производственный запуск

```sh
bun run build
bun run start
```

Сборка создаёт dist/server.mjs и ресурсы клиента в dist/client. Для запуска нужны dist,
package.json и установленные зависимости. Готовый сервер автоматически обслуживает
собранный клиент; NODE_ENV=production дополнительно задавать не требуется.
Сервер находит ресурсы относительно своего файла, независимо от текущего каталога.
HOST и PORT настраиваются окружением. Ошибка порта или старта завершает процесс
с ненулевым кодом, чтобы диспетчер процессов мог заметить отказ.
GET /api/health проверяет доступность сервера, а не состояние Firestore или качество распознавания.
В готовой production-сборке ИИ-запросы требуют Firebase-вход и права редактирования.
При отдельном размещении интерфейса задаются VITE_AI_API_BASE_URL во время сборки
и ALLOWED_WEB_ORIGINS на сервере. См. [инструкцию публикации](docs/website-deployment.md).

Правила Firebase публикуются отдельным действием по [инструкции доступа](docs/firestore-security.md).
Запуск приложения и push кода сами по себе не обновляют правила в рабочей базе.

## Сохранность данных

- Облачная очередь очищается только после подтверждения всего пакета; более новые
  изменения во время отправки остаются в очереди. См. [описание синхронизации](docs/cloud-sync.md).
- Локальная очередь сохраняется до завершения транзакции IndexedDB. При отказе
  остаётся в памяти, на экране появляется предупреждение с повтором сохранения.
- localStorage используется как компактный/исторический кеш, а не как подтверждение
  сохранения при отказе IndexedDB. Если IndexedDB недоступен, новые изменения
  остаются неподтверждёнными. Не закрывайте вкладку до успешного повтора.
- Закрытие вкладки с незаписанными изменениями вызывает стандартное предупреждение
  браузера, когда браузер разрешает его показать. Аварийное завершение браузера
  не гарантирует сохранения неподтверждённых изменений.
- JSON-архив включает активных людей, семьи, события, источники, места и исследовательские
  коллекции. Это не архив всей установки: отдельные заметки, корзина, история слияний,
  локальные настройки и сами файлы вложений в него не входят.
- Перед заменой локальных данных из облака требуется успешно записанная резервная
  точка. Если во время чтения появились локальные правки, замена отменяется.
- Люди, добавленные из ШІ-анализа, имеют статус needs_verification. Год документа
  не записывается как год рождения, пол и факт смерти не выдумываются.

Локальная копия не заменяет внешнюю резервную копию: перед изменением правил,
импортом или слиянием сохраняйте экспорт и проверяйте восстановление.

## Ограничения проверки

Автоматические тесты не подтверждают развёртывание правил, доверенность рабочего
whitelist, доступ через настоящий Google sign-in, точность чтения конкретного
почерка или полный пользовательский сценарий в браузере. Перед первым публичным размещением AI API нужно проверить настоящий вход,
доступ к whitelist и ограничения расхода выбранного хостинга.
